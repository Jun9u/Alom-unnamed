# 바르미 (Barumi) 프론트엔드

[편집 가능한 모바일 화면과 클릭 흐름](https://www.figma.com/design/es0XYfuSqyZffFkHdGfahX?node-id=8-47)

마이크로 한국어 예문을 읽고 시각적 피드백을 확인하며 반복 연습하는 모바일 웹앱이다. React, TypeScript, Vite, CSS Modules, Chart.js와 브라우저 녹음 API를 사용한다. 기본 실행은 목업 모드이며 실제 AI·백엔드는 연결하지 않았다.

## 실행

Node.js 22.17에서 확인했다. 저장소의 `frontend/` 폴더에서 다음을 실행하고 터미널에 표시되는 localhost 주소를 연다.

```sh
npm ci
npm run dev
```

타입 검사만 실행하려면 `npm run typecheck`, 타입 검사와 배포 파일 생성을 함께 하려면 `npm run build`를 사용한다. 휴대전화에서 컴퓨터의 LAN 주소로 직접 접속할 때는 마이크 접근을 위해 HTTPS가 필요하다.

## 화면과 시연

홈 중앙 마이크 → 녹음 종료 → 분석 요청 → 저장된 개별 결과. 하단 학습 기록에서 날짜·문장·점수로 회차를 선택하거나 **학습 분석하기**로 최근 7일 평균과 전체 기록의 반복 구간을 확인한다. **예문** 메뉴에서는 다른 카테고리의 문장을 고를 수 있다.

**설정 → 시연 설정**에서 성공·무음·잡음·다른 문장·분석 불가·오류·지연과 빈 목록·기록을 재현한다. 목업 결과의 원문·점수·구간·일시·입력 크기 요약은 현재 브라우저의 localStorage에 저장한다. 음성 파일은 저장하지 않는다. 최초 실행에는 시연 기록 4개가 제공된다. 평균에서 null 점수는 제외하며 글자 하이라이트는 원문에만 적용한다. 파형의 시간 위치와 글자 오류의 대응 정보는 제공되지 않는다.

| 구성              | 역할                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| src/main.tsx      | 화면 이동, 예문 목록, 시연 설정                                        |
| src/Practice.tsx  | 대기·권한·녹음·녹음 확인·업로드·분석·완료·오류 상태, 재녹음, 결과 표시 |
| src/record.ts     | getUserMedia, MediaRecorder, Canvas 파형, 자동 종료와 자원 정리        |
| src/History.tsx   | Chart.js 점수 추이와 동일한 값을 읽을 수 있는 날짜별 표                |
| src/api.ts        | 공통 타입, 목업, fetch 어댑터, UTF-16 범위 검증                        |
| src/ui.module.css | 390px 설계 기반 반응형 스타일과 토큰                                   |

## API 교체와 협의 사항

아래는 연동 제안이다. 프로젝트 루트의 `.env.local`에 `VITE_API_BASE_URL=https://api.example.com`을 설정하고 Vite를 재시작하면 fetch 어댑터가 활성화된다. 화면은 동일한 Api 인터페이스를 호출하며 실제 모드에서는 시연 설정이 숨겨진다.

| 요청                  | 응답                                                                  |
| --------------------- | --------------------------------------------------------------------- |
| GET /sentences        | Sentence 배열. id, category, text                                     |
| POST /attempts        | multipart/form-data에 sentenceId와 file. processing 또는 최종 Attempt |
| GET /attempts/:id     | 해당 요청의 현재 Attempt                                              |
| GET /learning-records | Entry 배열. Attempt에 savedAt과 선택적 levels(입력 크기 요약)를 포함  |

Attempt에는 attemptId, sentenceId, sourceText, status(processing/completed/failed), score(number 또는 null), issues([{start,end,description}]), errorCode, message가 들어간다. 분석 불가는 failed와 null 점수로 반환한다. 전송·서버 장애와 분석 불가 응답을 구분한다. processing인 동안 폴링하며 화면 이동 시 요청을 취소한다. 실제 운영 전 HTTP 타임아웃, 재시도 정책, 요청 멱등 키와 서버 작업 취소 지원 여부를 합의해야 한다.

범위는 응답의 sourceText 원문에 대한 **UTF-16 코드 단위, 0부터 시작, start 포함·end 제외**다. 예를 들어 ‘안녕하세요.’의 [0,2)는 ‘안녕’이다. 서버가 정규화한 원문을 돌려주면 그 문자열을 그대로 렌더링한다. NFC ‘한’과 분해 자모 문자열은 길이가 다르다. 프론트는 범위를 정렬하고 음수·경계 초과·역전·중복·겹침 및 글자소 내부 경계를 제외한다. 음소 결과를 표시하려면 음소-원문 구간 대응과 시간 정렬 계약이 추가로 필요하다.

파일은 브라우저가 생성한 Blob MIME을 유지하며 가능한 컨테이너를 확인한 뒤 녹음한다. 서버는 실제 미디어 검증, 디코딩, 채널·샘플링 레이트 변환, 최대 크기와 보관·삭제 정책을 담당한다. 실제 서비스는 서버 인증으로 사용자별 연습과 조회 권한을 분리해야 한다. 쿠키 인증 시 CORS, credentials, CSRF 정책과 사용자 기준 날짜·시간대를 합의해야 한다. 3~5초는 향후 전체 시스템의 응답 목표이며, 목업의 타이머는 성능 측정값으로 사용할 수 없다.

## 확인 결과 및 남은 검증

- Chrome 데스크톱의 가상 마이크로 권한 허용, 브라우저 권한 거부, 녹음 파일 생성, 수동 종료, 실제 60초 경과 후 자동 종료, 종료·화면 이동 후 트랙 해제를 확인했다.
- 시연 성공 점수와 밑줄, 재녹음 시 이전 결과 초기화, 서버 오류 후 같은 녹음으로 재요청, 무음의 null 점수, 지연 중 다른 예문으로 이동했을 때 늦은 결과 무시를 확인했다. 목업 어댑터에서 잡음·다른 문장·일반 분석 불가와 네트워크 오류도 확인했다.
- 한글 분해 자모와 이모지 내부 경계, 겹침, 음수·범위 초과를 제외하는 검사를 확인했다.
- Chrome에서 목록은 360·390·430·900px로, 기록은 360px로 가로 넘침을 검사했다. 목록 오류·빈 상태, 빈 학습 기록도 확인했다.
- Figma에는 390px 화면 15개가 있는 초기 설계와 스케치 v2 페이지가 있다. 대표 인사 예문의 이동을 연결했다. 카테고리 필터와 다른 예문의 개별 연습, 실제 권한 창·타이머·음성 입력은 프론트엔드에서 동작한다. 오류와 빈 상태는 Figma에서 개별 프레임으로 볼 수 있다.
- 실물 마이크의 소리·음질, iOS Safari와 Android 실기기, 보조 기술 사용성, 실제 백엔드 응답·모델 정확도는 미확인이다.

스케치 v2에는 오늘의 연습·녹음 중·녹음 확인·개별 분석·학습 기록·종합 분석 화면이 있다. Chrome 가상 마이크로 홈 녹음, 분석 저장, 새로고침 후 같은 기록 열기, 반복 구간 집계와 종합 분석 화면의 360·390·430px 가로 넘침을 검증했다.

## 기록의 음성 재생
바르미는 분석을 마친 실제 녹음 Blob을 attemptId별로 현재 탭의 메모리에 보관한다. 새로고침하거나 탭을 닫으면 음성이 해제되며 분석 기록은 기존처럼 남는다. 상세 화면을 벗어나면 재생을 멈추고 임시 URL을 해제한다. 시연 기록의 파형은 예시이며 음성은 없다. 중앙 마이크는 기본 연습으로 이동하는 버튼이며 홈 화면 안의 마이크가 녹음을 시작한다. 심화 학습의 두 주제는 준비 중이다.

실제 서비스에서는 분석 직후 서버 음성 삭제를 기본으로 하고, 장기 다시 듣기를 도입하기 전에 재생용 별도 동의·보관 기간·철회 및 삭제 절차·사용자별 접근 권한을 합의해야 한다. 모델 학습용 수집 동의는 재생용 저장 동의와 별개다.
